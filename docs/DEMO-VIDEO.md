# ORBITAL 기능 설명과 3분 시연 영상 구성

작성 기준: 2026년 10월 26일. 실제 RSS 조회, Python 공개 본문 추출, GPT 본문 요약과 아이디어 생성, 보고서 편집·PDF 출력을 로컬 검증했습니다.

## 1. 서비스 한 문장 소개

ORBITAL은 여러 국가의 뉴스에서 사업 신호를 찾고, 키워드 한 번의 선택으로 관련 기사와 국가를 연결한 뒤 사업 아이디어·평가점수·검토 단계·검증 계획·최소 PoC 예산·결재용 보고서까지 준비하는 전략 검토 워크스페이스입니다.

사용자는 수집된 정보를 읽는 데서 멈추지 않고, 그 정보를 어떤 사업으로 구체화하고 무엇을 검증해야 하는지까지 한 화면에서 이어갈 수 있습니다. 자동 생성 결과는 수정 가능한 초안이며 최종 결재와 측정 실적은 담당자가 확인해 기록합니다.

## 2. 문제와 해결 방식

### 해결하려는 문제

- 여러 국가·언론사에 흩어진 기사에서 중요한 변화와 반복 신호를 찾는 데 시간이 듭니다.
- 기사 읽기, 아이디어 작성, 사업성 평가, 검토 이력, 예산 작성, 보고서 작성이 각각 분리되어 있습니다.
- 보고서가 작성된 뒤 어떤 기사에서 판단이 출발했는지 다시 추적하기 어렵습니다.
- 팀원별 파일이나 로컬 저장소를 쓰면 같은 안건에 대한 수정과 검토 이력이 흩어집니다.

### ORBITAL의 해결 방식

`기간·대륙 선택 → 실제 뉴스 검색 → 기사 빈도에 따른 키워드 추천 → 키워드 클릭 → 관련 기사·국가 추출 → 아이디어·점수·단계·검증계획 생성 → 보고서·PDF`

기사와 사업 아이디어를 근거 ID로 연결하고, 생성된 결과를 서버 PC의 SQLite에 함께 저장합니다. 같은 LAN 주소에 접속한 팀원은 같은 데이터를 조회하고 수정합니다.

## 3. 화면별 상세 기능

### A. 글로벌 인사이트

1. **기간 선택:** 최근 7일, 30일, 90일 또는 시작일·종료일 직접 지정. 날짜는 한국 시간 기준으로 판단합니다.
2. **대륙 선택:** 전 세계, 아시아, 유럽, 북아메리카, 남아메리카, 아프리카, 오세아니아.
3. **실시간 뉴스 검색:** 기간·대륙을 바꾸면 해당 범위의 검색을 실행합니다. '뉴스 검색'으로 다시 조회할 수도 있습니다.
4. **출처 확장:** 기존 NASA·ESA 공식 RSS와 6개 분야의 Google News 검색 피드를 유지하고, 52개국에 등록된 주요 매체를 국가별 5곳씩 추가 검색합니다. 등록 매체는 총 260곳입니다. '전 세계 모든 국가'나 '통계상 상위 5위'라는 의미는 아니며 검색용으로 선정한 주요 매체 목록입니다.
5. **빈도 기반 키워드:** 기사에서 등장한 키워드·주제어의 문서 빈도를 집계합니다. 한 기사에 같은 단어가 여러 번 나와도 키워드당 한 건으로 계산합니다. 매체명과 일반적인 불용어를 제외하고, 동의어를 묶어 주제별 빈도를 보여줍니다.
6. **한 번의 선택:** 키워드 버튼을 누르면 관련 기사 묶음과 연결된 업무 초안이 자동으로 준비됩니다. 사용자가 각각의 메뉴에서 다시 빈 양식을 채울 필요가 없습니다.
7. **최신순 기사:** 관련 기사를 발행일 최신순으로 보여주며 결과 내 검색과 페이지 이동을 지원합니다.
8. **국가 연결:** 제목에 나온 국가를 우선 추출하고, 국가가 명시되지 않으면 확인된 매체 소재지를 이용합니다. 두 방식은 기사에 구분해 표시합니다. 국가를 확인하지 못한 기사에 임의의 국가를 붙이지 않습니다.
9. **지구본:** 관련 기사가 있는 국가에만 빛나는 거점을 표시합니다. 국가를 클릭하면 해당 국가 기사로 좁혀 보고, 지구본을 그 국가 방향으로 볼 수 있습니다. 회전·확대·축소·초기화를 지원합니다.
10. **진행 상황:** RSS 검색, 기사 분석, 한국어 요약 등의 진행 상태와 실패 사유를 확인할 수 있습니다.

### B. 뉴스·지식베이스와 한국어 요약

- 기사 클릭 시 한국어 요약, 핵심 키워드, 출처, 발행일, 수집 시각, 관련 국가와 분석 근거를 확인합니다.
- 선택한 기사는 사업 검토 안건의 근거로 연결할 수 있습니다.
- 저장된 요약을 재사용하고, 같은 기사·같은 분석의 중복 생성을 줄입니다.
- 접근 차단이나 본문 추출 실패 항목은 분석 목록에서 제외하고 실패 내용을 기록합니다.
- **Python 본문 수집:** Google News 링크에서 원문 주소를 확인하고, Trafilatura로 공개 기사 본문을 추출합니다. 메뉴·광고·댓글을 줄인 본문 전체를 GPT에 전달해 한국어 요약과 핵심 키워드 3개를 생성합니다. 본문 확보·요약 실패 기사는 최종 분석에서 제외하며 제목만으로 요약을 대체하지 않습니다.
- **실제 검증 예:** 위성 키워드의 기사 2건 중 ABC 기사 본문 4,938자를 확보해 한국어 요약·키워드 3개·사업 아이디어 1개·의사결정 로그 초안 1개·검증 지표 3개·보고서를 생성했습니다. 다른 1건은 본문이 짧아 제외됐습니다. 이 시연 결과는 별도 QA DB에 저장돼 있으며 사용자의 기본 DB와 분리했습니다.
- Google News는 검색 입구이며, 기사 본문은 원문 매체가 공개한 페이지에서 가져오는 구조입니다. 로그인·유료벽·차단이 있는 매체의 본문까지 항상 가져오는 서비스는 아닙니다.

### C. 사업·투자 검토

- 선택한 기사들을 분야와 반복 신호로 묶어 고객 문제, 제공할 해결책, 대상 고객, 수익모델, 위험요인, 다음 행동을 가진 아이디어로 구체화합니다.
- 초안을 먼저 준비하고 GPT가 기사 근거를 바탕으로 내용을 구체화합니다.
- 평가 항목은 ① 사업 적합도 30%, ② 고객 수요·관심 신호 25%, ③ 수익성 신호 25%, ④ 기술·차별성 가설 20%입니다. 각 항목을 1~5점으로 평가해 100점으로 환산합니다.
- 기본 단계 기준은 투자검토 60점 이상, PoC·실증 75점 이상, 추진 제안 85점 이상입니다. 기준 미달은 기회 발굴 단계에서 계속 검토합니다.
- 사용자가 단계 진입 점수를 변경할 수 있습니다. 새 기준은 새 분석에 적용되며 과거 이력은 보존합니다.
- 안건을 클릭하면 사업 가설·고객·해결책·수익모델·위험·담당자·점수·다음 행동·근거 기사를 수정할 수 있습니다.
- 점수를 수정하면 자동 분류를 다시 계산합니다. 단계 수동 지정 기능으로 사용자가 검토 단계를 고정할 수도 있습니다.
- 기사 빈도는 실제 구매 의향이나 시장 규모를 확정한 값이 아닙니다. 점수의 산식과 기사 근거를 함께 보여줍니다.
- 모든 칸에 억지로 안건을 채우는 방식이 아니라, 기준을 충족한 아이디어가 해당 단계로 배치되는 방식입니다.

### D. 의사결정 로그

- 아이디어의 점수와 단계 기준 통과·미달 결과를 판단 근거와 함께 자동 초안으로 남깁니다.
- 관련 기사와 후속 검증 조건을 연결합니다.
- 의사결정 로그 초안의 제안 단계, 판단 근거, 후속 조건을 수정할 수 있습니다.
- 자동 분류 초안과 담당자의 확정 의사결정은 구분합니다. 초안이 생성됐다고 실제 투자 승인이나 계약이 발생한 것은 아닙니다.

### E. 가정·실적 관리

- 아이디어마다 고객 인터뷰, 데이터 확보율, PoC 예산 등의 검증 지표와 목표·단위·기한을 자동으로 준비합니다.
- 실제 측정 전의 실적은 비워 둡니다. 발생하지 않은 성과를 만들어 넣지 않습니다.
- 사용자는 지표와 목표를 수정하고, 확인된 실적과 그 근거를 입력합니다.
- 목표 대비 실제 값의 차이와 실적 이력을 남겨 후속 검토에 사용할 수 있습니다.

### F. 수집·업데이트

- 어느 피드가 실제로 응답했는지, 몇 건이 반환됐는지, 새 기사는 몇 건인지 확인합니다.
- 국가별 주요 매체 5곳과 매체 도메인을 펼쳐 볼 수 있습니다.
- 분석 진행과 오류를 확인하고 현재 범위의 검색이나 미완료 분석을 다시 실행합니다.
- 동일 URL을 중복 저장하지 않고 최신 검색 확인 시각을 갱신합니다.
- 정시 자동 검색 스케줄러는 별도 기능입니다. 화면의 자동 새로고침은 저장 상태 조회이며, 정시 외부 뉴스 검색이라고 표현하지 않습니다.

### G. 최종보고서

- 수집·업데이트 메뉴 아래에 최종보고서 메뉴가 있습니다.
- 기사 근거와 생성된 아이디어·평가·예산·추진 계획을 사업 아이디어 보고안으로 묶습니다.
- 실제 공개된 Five Case Model 사업제안서 템플릿을 참고해 결재 요청사항, 사업 필요성, 대안 비교, 고객·수익모델·조달, 예산, 일정·책임, 위험요인, 기사 근거로 구성합니다.
- 기안·검토·결재란을 포함하며 작성자·부서·검토자·결재자와 각 본문 항목을 수정할 수 있습니다.
- 최소 예산은 기존 PC와 공개 자료를 사용하는 8주 PoC 가정입니다. 고객 인터뷰, 데이터 정제, 프로토타입, 검증, 테스트 환경, 소규모 데이터 이용 비용과 예비비로 계산합니다.
- 산식은 `항목별 수량 × 계획 단가의 합계 + 예비비`입니다. 수량·단가·예비비율을 직접 바꿀 수 있고 합계가 다시 계산됩니다.
- 계획 단가는 내부 가정이며 실제 견적이나 확정 지출은 아닙니다. 위성 제작·발사나 대규모 상용 인프라 비용까지 포함한 예산이 아닙니다.
- 편집한 DB 자료로 A4 PDF를 생성하고 다운로드합니다. 인쇄 화면에서 'PDF로 저장'할 수도 있습니다.

### H. 협업·저장과 실행

- 서버 PC 한 대에서 포트 37214로 호스팅합니다. 팀원은 같은 Wi-Fi·LAN에서 서버 PC 주소로 접속합니다.
- 모든 브라우저가 같은 SQLite를 사용하므로 수정한 안건과 보고서를 공유합니다.
- 서버를 다시 켜도 저장된 기록과 완료된 분석은 보존됩니다.
- 같은 키워드·같은 기사 묶음의 분석은 기존 이력을 열어 중복 생성과 재분석을 줄입니다.
- 다른 사람이 먼저 수정한 경우 revision 충돌을 안내해 최신 내용을 확인하도록 합니다.
- Node.js로 웹과 API를 제공하고, Codex 로그인으로 GPT-6 Luna / Low를 호출합니다. Python은 기사 본문 추출을 담당합니다. 서버 PC에만 Python·Codex가 필요하고 팀원은 브라우저로 접속합니다.

## 5. 3분 내레이션 초안

### 0:00–0:15

“사업 기회를 찾기 위해서는 여러 나라의 뉴스를 읽고, 공통된 변화를 분석한 뒤 다시 기획서와 예산을 작성해야 합니다. ORBITAL은 이 과정을 하나의 검토 흐름으로 연결합니다.”

### 0:15–0:40

“먼저 탐색할 기간과 대륙을 정합니다. 기존 공식 뉴스 피드에 국가별 주요 매체를 더해 관련 기사를 검색합니다. 기사에 자주 등장하는 키워드를 빈도순으로 추천하기 때문에, 지금 어떤 주제가 반복해서 나타나는지 빠르게 확인할 수 있습니다.”

### 0:40–1:05

“키워드를 선택하면 관련 기사와 국가가 추출됩니다. 기사들은 최신순으로 정렬되고, 지구본에는 기사가 연결된 국가만 빛나는 거점으로 나타납니다. 국가를 클릭해 기사를 좁혀 보고, 기사 상세에서 한국어 요약과 출처를 확인할 수 있습니다.”

### 1:05–1:40

“같은 선택으로 사업·투자 검토도 준비됩니다. 반복된 기사 신호를 고객 문제와 해결책, 수익모델을 갖춘 아이디어로 구체화합니다. 사업 적합도, 수요 신호, 수익성과 차별성을 평가해 점수를 계산하고, 단계별 기준에 따라 투자검토와 실증 등 다음 검토 단계를 제안합니다. 사용자는 안건을 열어 내용과 점수, 기준을 직접 수정할 수 있습니다.”

### 1:40–2:00

“아이디어가 만들어지는 동시에 판단 근거와 후속 조건도 기록됩니다. 고객 인터뷰, 데이터 확보율, 예산 등의 검증 지표와 목표를 준비하고, 실제 측정 결과가 나오면 실적과 근거를 추가해 비교합니다.”

### 2:00–2:15

“수집·업데이트 화면에서는 어느 피드에서 몇 건을 가져왔는지, 국가별 어떤 매체를 검색하는지 확인합니다. 처리 상태와 실패 내역을 남겨 결과의 출처를 다시 추적할 수 있습니다.”

### 2:15–2:50

“최종보고서는 기사 근거와 사업 아이디어, 평가점수, 추진 계획을 결재용 보고안으로 정리합니다. 기존 장비와 공개 데이터를 활용하는 최소 PoC 예산도 항목별 수량과 단가, 예비비를 기준으로 추천합니다. 작성자와 결재란, 본문과 예산을 수정하면 수정된 자료로 PDF를 출력할 수 있습니다.”

### 2:50–3:00

“ORBITAL은 뉴스 탐색을 사업 아이디어, 검증 계획, 보고서까지 연결합니다. 자동화된 초안을 사람이 검토하고, 팀이 같은 근거와 기록으로 함께 발전시키는 워크스페이스입니다.”

## 6. 촬영 전 준비와 표현 주의사항

1. 기사 수집과 AI 처리를 미리 완료한 분석 하나를 준비합니다. 실제 대기 시간은 진행 상태 화면으로 짧게 보여주고 필요한 경우 장면 전환으로 줄입니다.
2. 시연 순서는 `범위 → 키워드 → 지구본 → 기사 → 사업 검토 → 의사결정 로그 → 검증 지표 → 출처 → 보고서 → PDF`가 자연스럽습니다.
3. 보고서는 미리 준비된 분석 이력을 사용하면 촬영 중 기다리는 시간을 줄일 수 있습니다. 새로운 키워드를 누르면 새로운 처리가 시작될 수 있습니다.
4. “투자를 자동 승인합니다”보다 “다음 검토 단계를 제안합니다”라고 설명합니다.
5. “매출과 실제 성과를 예측해 확정합니다”보다 “사업 가설과 검증 목표를 준비합니다”라고 설명합니다.
6. “전 세계 모든 국가의 상위 5대 언론사를 분석합니다”보다 “52개국의 주요 매체를 국가별 5곳씩 등록해 검색합니다”라고 설명합니다.
7. “최소 예산이 실제로 확정됐습니다”보다 “항목별 계획 단가에 따른 PoC 예산 초안입니다”라고 설명합니다.
8. “공개된 기사 본문을 수집해 한국어로 요약하며, 본문을 확보하지 못한 항목은 제외합니다”라고 설명합니다. 모든 매체의 기사 본문을 확보한다고 표현하지 않습니다.
9. 초기에는 임시 초안이 즉시 나타나고 본문 확인·요약 후 최종 결과가 갱신됩니다. '클릭하는 즉시 분석 완료'가 아니라 '클릭 한 번으로 전체 작업 시작'입니다.
10. 빈도 추천은 검색된 제목·RSS 설명에 기반하고, 최종 요약과 사업 아이디어는 확보된 기사 본문에 기반합니다. 평가점수는 규칙 산식이며 AI 투자예측 점수가 아닙니다.
